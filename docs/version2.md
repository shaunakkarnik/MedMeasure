# Version 2 implementation

V2 asks whether mask supervision improves measurements generated by MedVision.
The text and joint experiments start from the same pinned checkpoint and use
the same training rows, shuffle seed, image processing, and vision adapters.
Direct partial unfreezing remains a proposed experiment.

## Follow one training example

1. `scripts/version2.py::main` loads the experiment configuration and dataset/model
   pins. It validates manifests against the official annotation plan and checks
   that training, validation, and test cases are disjoint.
2. `version1_data.load_image` loads the native axial CT slice and checks its
   dimensions, affine, orientation, and pixel spacing. It applies the KiTS23
   soft-tissue window and converts the slice to RGB.
3. `version2.sizing_inputs` builds the system and user messages from
   `configs/version2-prompts.json`. The question includes source-image dimensions
   and physical pixel spacing. The processor resizes the image.
4. `version2.answer_inputs` appends reference axis lengths and an end token.
   Prompt labels are masked with `-100`, so token cross-entropy supervises
   the reference completion.
5. `version2.training_losses` computes answer loss. In the joint arm, hooks
   capture vision blocks 7, 15, 23, and 31. The existing spatial restoration
   function undoes window and merge-block packing before decoding.
6. The joint decoder uses these spatial maps and the last prompt token's
   language state to predict a native-resolution mask. Causal attention keeps
   that prompt state independent of subsequent reference answer tokens.
7. The optimizer updates the vision adapters from both objectives and updates
   decoder parameters from the mask objective. The language backbone passes
   gradients through to the vision adapters.

## Parameters and losses

`VisionLoRA` adds a down-projection and up-projection around each selected
vision QKV projection. Rank 8 and alpha 8 give a multiplier of one.
The up-projection starts at zero, so the initial adapter output is zero.
Adapter parameters use float32. Original model parameters stay frozen.

The text objective is answer-token cross-entropy. The joint objective adds
`mask_weight × (binary cross-entropy + soft Dice loss)`. The initial
mask weight is 1. The implementation reuses `version1.segmentation_loss`
and `TargetMaskDecoder`.

V1 intermediate feature maps remain useful to the joint decoder. Only the
selected later blocks receive adapters, so earlier captured maps stay fixed.
The prompt-conditioned query and later visual map provide paths for mask loss
to update the adapters.

See `configs/version2-kits23.json` for learning rates, adapter placement,
image token budget, generation limit, and seed. Both experiments use batch
size one, AdamW, and gradient clipping. Training performs fresh image forward
passes because the V1 feature cache predates adaptation.

## Evaluation and checkpoints

Evaluation loads the pinned backbone and the saved vision adapters, then
generates text from the scan, question, and spacing. The mask decoder is
omitted. `score_answer` parses a tagged pair with optional parentheses.
Unparseable or nonfinite answers count as failures.

Per-row MAE averages absolute error across the two axes. MRE averages their
relative errors. Within-10% accuracy uses the strict condition MRE < 0.1,
with failures counted in the all-row denominator. Axis references follow the
baseline's float16 label precision.

Every completed epoch generates held-out validation answers. Selection
maximizes all-row within-10% accuracy, then success fraction, then minimizes
success-only MRE. `best.pt` stores the selected checkpoint and `last.pt`
stores the last completed epoch. Checkpoints include adapters, decoder state
for joint runs, optimizer state, and an experiment contract. Resume repeats
an interrupted epoch and requires matching source, manifests, settings,
objective, dtype, and Torch version.

Source hashes are part of that contract. Keep a copy of the training revision
when evaluating or resuming existing checkpoints. The original V2 submission
snapshot is commit `14e92dd`. ICE jobs launched from copied files can report
the older checkout SHA, so use the recorded source hashes to identify their
actual runtime files.

## Prompt provenance and interpretation

The system prompt follows the pinned upstream
`src/medvision_bm/rft/verl/rft_prompts.py`. The sizing template was recovered
from saved baseline sample inputs, with image dimensions and spacing replaced
by runtime values. The upstream commit is recorded in
`configs/kits23-pilot.json`.

The V2 pipeline uses V1 image rendering and a local text parser. Evaluate
frozen MedVision through this pipeline for the matched starting point.
Reference completions currently supervise final axis lengths. The task prompt
also requests the model's established reasoning format. Validation outputs
should be inspected alongside aggregate scores.

The corrected prompt and both training objectives passed small ICE execution
checks. Full training jobs have been submitted, and their results remain
pending. [ICE commands](ice-version2.md) and [current state](../CONTINUITY.md)
record how to reproduce and continue those runs.
